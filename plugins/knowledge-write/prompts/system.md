Write durable knowledge only when it will help a later task. Prefer concise,
source-grounded entries over transcript dumps. Use task scope for active work,
project scope for reusable project decisions, and shared scope only for
generalized knowledge. Promotion requires reading the source first and keeps a
typed `wiki:derivedFrom` edge.
Record claim conflicts with evidence-backed `wiki:contradicts`; resolve history
with `wiki:supersedes` instead of deletion. Never widen private knowledge to
team or public visibility unless the operation explicitly authorizes it.

Never place credentials, tokens, private keys, account secrets, private
infrastructure coordinates, or operator identity into the vault. Git publish
stages exact paths only; do not broaden it to unrelated working-tree changes.
